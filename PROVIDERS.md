# Provider and local model guide

Verified against official documentation on **12 October 2026**. These are documented options, not live tests with student credentials. Quotas, countries, model access, aliases, and catalog entries can change. Do not add a payment method for this assignment; use another listed free option or Ollama if an account is ineligible.

## Verification decisions and endpoint policy

- Gemini Flash/Flash-Lite: the current API pricing page lists 3.5 Flash-Lite and 3.8 Flash with free input/output access. Older 2.5 defaults were replaced. API availability must not be inferred from consumer Gemini subscription announcements.
- Groq's [deprecation notice](https://console.groq.com/docs/deprecations) replaces `qwen/qwen3.6-27b` with `qwen/qwen3.8-27b` for free/developer use. The latter appears in its current free-plan limits. Qwen3.5 local tags are not assumed to be Groq API IDs. Older `qwen/qwen3-32b` is not a preset.
- Mistral's official no-card Free-mode walkthrough actually calls `mistral-small-latest`. This is stronger evidence than assuming all models in its public catalog are enabled for every free account. It is a rolling alias; the documented Small 4 snapshot is `mistral-small-2603`. Check account discovery before pinning another model.
- OpenRouter free discovery is explicitly filtered to `:free` IDs. A custom model lacking this suffix (other than `openrouter/free`) displays a paid-access warning. The app does not switch to a paid model when free capacity is exhausted. The free router is convenient but a poor choice for controlled model comparisons because its selected model varies; reported model IDs are saved.
- Shared OpenAI-compatible presets use only `https://api.groq.com/openai/v1`, `https://openrouter.ai/api/v1`, `https://api.mistral.ai/v1`, and `https://api.openai.com/v1`. Students can edit model IDs, not cloud endpoints. Ollama's URL is configurable and receives only the placeholder key `ollama`, never any cloud key.
- SDK-level retries are disabled. The app itself retries rate limits and provider outages up to twice, visibly, and records the retry count with each result. Structured output uses schemas for verified OpenAI/Groq models, JSON mode for compatible backends, Gemini JSON schemas, and an Anthropic forced tool result. [Groq structured output support](https://console.groq.com/docs/structured-outputs) is model-specific. Custom models can reject these settings: the user can turn structured mode off and explicitly rerun. No fallback request occurs silently.

## Local hardware guide

Download sizes below are approximate official Ollama catalog sizes, varying with quantization and platform. **Working-memory ranges are planning estimates**, not vendor guarantees or measured benchmarks. They assume short classroom prompts and modest context (roughly 2K–4K tokens), one model loaded at a time. The operating system/browser need additional headroom. Advertised 128K/256K context limits do not mean those contexts fit on a laptop.

| Hardware | Start with | Approximate download | Estimated memory for the model and short context | Practical limits |
|---|---|---|---|---|
| CPU laptop, about 8 GB RAM | `qwen3.5:2b`; `gemma3:1b` if tight | Qwen 2.7–3.1 GB; Gemma about 0.8 GB | Qwen roughly 4–6 GB RAM; Gemma roughly 2–3 GB | Close memory-heavy apps, use short scenarios. Generation can take minutes. Avoid large batches; these are weak judges. |
| 16 GB RAM or 6–8 GB GPU | `qwen3.5:4b`, `gemma3:4b`; `ministral-3:3b` or `phi4-mini:3.8b` alternatives | Qwen 3.3–4.0 GB; Gemma 3.4 GB; Ministral 3.0 GB; Phi 2.5 GB | Typically roughly 5–8 GB RAM/VRAM for a 4B model; system RAM still needed | GPU fit depends on context and quantization. CPU offload is slower. Newer `gemma4:e2b` is larger than its effective parameter label suggests. |
| 12 GB or larger GPU, ideally 24–32 GB system RAM | `qwen3.5:9b`; `gemma4:e4b` or `ministral-3:8b` alternatives | Qwen 6.6–7.6 GB; Gemma 6.6–9.5 GB; Ministral 6.0 GB | Roughly 9–12+ GB VRAM, depending on model/context | Begin with short context and monitor memory. Near-limit models may offload to CPU. Larger does not guarantee trustworthy judging. |

Verified tags and sizes: [Qwen3.5](https://ollama.com/library/qwen3.5/tags), [Gemma3](https://ollama.com/library/gemma3/tags), [Gemma4](https://registry.ollama.com/library/gemma4/tags), [Ministral 3](https://ollama.com/library/ministral-3/tags), [Phi4-mini](https://ollama.com/library/phi4-mini/tags). Gemma4 E2B downloads span roughly 4.6–7.5 GB; treat it as an option for a 16 GB system, not the default for an 8 GB laptop. Model versions can require a recent Ollama release.

Use `ollama ps` to see whether a model is on CPU/GPU. Ollama supports automatic GPU acceleration on supported hardware and CPU fallback; [memory, GPU and context guidance](https://docs.ollama.com/faq). A local model with no cloud suffix works without external credentials. Pulling a model requires internet once; inference can then be offline.

Small models are valuable for observing instruction failures and prompt sensitivity. Their inability to follow JSON schemas or recognize subtle conflicts is itself a limitation to report, not evidence that the candidate is misaligned. Where possible compare a small local candidate with a stronger free cloud judge, then repeat with a local judge to study disagreement.
